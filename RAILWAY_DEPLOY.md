# Развертывание Lampac на Railway

## ⚡ РЕКОМЕНДУЕМЫЙ СПОСОБ: Готовый Docker образ

Самый быстрый и надежный способ - использовать готовый Docker образ вместо сборки из исходников.

### Вариант 1A: Через Railway Dashboard (БЕЗ GitHub)

1. **Откройте Railway.app**
   - Нажмите "New Project"

2. **Выберите "Deploy from Docker Image"**
   - В поле "Image" введите: `immisterio/lampac:latest`
   - Нажмите "Deploy"

3. **Настройте переменные окружения**
   - Перейдите в Settings → Variables
   - Добавьте переменную:
     ```
     PORT=${{RAILWAY_PUBLIC_PORT}}
     ```

4. **Настройте порт**
   - Settings → Networking
   - Включите "Public Networking"
   - Railway автоматически назначит порт

5. **Готово!**
   - Откройте URL вида: `https://your-app.up.railway.app/admin`

**Преимущества этого способа:**
- ✅ Сборка занимает 30 секунд вместо 10 минут
- ✅ Нет проблем с логированием (готовый образ оптимизирован)
- ✅ Нет проблем с обрывом сети при скачивании
- ✅ Стабильная версия Lampac
- ✅ Автоматические обновления (если используете :latest)

## Вариант 1B: Через GitHub + простой Dockerfile

Используйте `Dockerfile.simple` из репозитория:

1. В Railway выберите ваш GitHub репозиторий
2. Railway автоматически найдёт `Dockerfile.simple`
3. В Settings → Build укажите: `Dockerfile Path: Dockerfile.simple`

## Вариант 2: Сборка из исходников (медленно, но гибко)

1. **Fork или Push этого репозитория в ваш GitHub**

2. **Перейдите на Railway.app**
   - Откройте https://railway.app
   - Нажмите "Start a New Project"
   - Выберите "Deploy from GitHub repo"

3. **Выберите репозиторий**
   - Авторизуйте Railway для доступа к GitHub
   - Выберите этот репозиторий (Lampac)

4. **Railway автоматически определит Dockerfile**
   - Билд начнется автоматически
   - Дождитесь завершения развертывания (~5-10 минут)

5. **Получите URL вашего приложения**
   - Railway сгенерирует URL вида: `https://your-app-name.up.railway.app`
   - Или настройте свой домен в настройках

6. **Доступ к приложению**
   - Откройте `https://your-app-name.up.railway.app/admin` для доступа к админке
   - Плагины доступны по адресам:
     - Все плагины: `https://your-app-name.up.railway.app/on.js`
     - Онлайн: `https://your-app-name.up.railway.app/online.js`
     - И т.д. (см. основной README.md)

### Вариант 2: Развертывание через Railway CLI


## Настройка переменных окружения

В настройках Railway вы можете добавить переменные окружения:

1. Перейдите в ваш проект на Railway
2. Откройте вкладку "Variables"
3. Добавьте необходимые переменные:

```
PORT=${{RAILWAY_PORT}}  # Railway автоматически назначит порт
```

## Конфигурация init.conf

После развертывания вы можете изменить конфигурацию через веб-интерфейс:

1. Откройте `https://your-app-name.up.railway.app/admin`
2. Измените настройки в соответствии с вашими потребностями
3. Перезапустите приложение

## Требования Railway

- **Memory**: Минимум 1GB RAM (рекомендуется 2GB)
- **CPU**: 1 vCPU
- **Disk**: ~2GB для образа Docker

## Особенности деплоя на Railway

1. **Порт**: Railway автоматически назначает порт через переменную окружения `PORT`
2. **HTTPS**: Railway автоматически предоставляет HTTPS
3. **Постоянное хранилище**: Для сохранения данных между деплоями настройте Railway Volume (не обязательно для базовой работы)

## Ограничения бесплатного плана

- ~500 часов работы приложения (при 1GB RAM)

## Проблемы и решения

### Приложение не запускается
- Проверьте логи в Railway Dashboard
- Убедитесь, что переменная PORT установлена правильно
- Проверьте, что используется достаточно памяти

### Нет доступа к админке
- Убедитесь, что вы используете правильный URL: `https://your-app.up.railway.app/admin`
- Проверьте логи на наличие ошибок

### Источники не работают
- Некоторые источники могут требовать дополнительной настройки в init.conf
- Проверьте, что rhub (Remote Control Hub) настроен правильно для источников, требующих его

### Ошибка: "Railway rate limit of 500 logs/sec reached"
**Проблема**: Railway ограничивает 500 логов в секунду, приложение при старте выводит ~2000+ строк конфигурации.

**Решение** (уже применено в Dockerfile v4):
- `weblog` отключен в init.conf (`"weblog":{"enable":false}`)
- `filelog:false` в init.conf (пытаемся отключить console dump)
- Уровень логирования .NET установлен в **Error**
- **ГЛАВНОЕ**: Добавлен grep фильтр в ENTRYPOINT, который пропускает только важные сообщения:
  - `load module`, `ModuleRepository`, `cloudflare`
  - `Application started`, `Exception`, `Error`
  - Блокирует вывод всего JSON конфига (~2000 строк → ~10 строк)

**Как это работает**:
Приложение всё ещё выводит конфиг в stdout, но grep фильтрует его до того как логи попадут в Railway, оставляя только критичные сообщения.

**Если нужен полный лог** (для отладки):
1. Временно измените ENTRYPOINT в Dockerfile, убрав grep:
   ```dockerfile
   ENTRYPOINT ["/bin/sh", "-c", "/usr/share/dotnet/dotnet Lampac.dll --urls \"http://0.0.0.0:${PORT}\""]
   ```
2. Пересоберите и задеплойте
3. **ВАЖНО**: Верните grep обратно после отладки!

**Почему не помогли ENV переменные Logging__**:
Они контролируют только .NET Framework логирование, но не контролируют вывод самого приложения Lampac (Console.WriteLine).

### Ошибка при сборке: "curl: (56) Recv failure: Connection reset by peer"
**Проблема**: Обрыв соединения при скачивании больших файлов (publish.zip ~238MB). Скорость падает с 56MB/s до 100KB/s и соединение обрывается.

**Причина**: Нестабильное соединение между Railway и GitHub servers.

**Решение** (уже применено в Dockerfile v2):
- `-C -` - автоматическое продолжение скачивания с места обрыва (resume)
- `--retry-all-errors` - повтор при ВСЕХ ошибках (включая connection reset)
- `--retry 15` - до 15 попыток
- `--retry-delay 5` - 5 секунд между попытками
- `--speed-limit 50000` - перезапуск если скорость < 50KB/s на 30 сек

**Что делать**:
1. **Просто перезапустите сборку** в Railway Dashboard - curl теперь продолжит с места обрыва
2. Если обрыв повторяется, curl автоматически повторит до 15 раз
3. Railway кеширует успешные слои Docker, поэтому повторные билды быстрее

**Почему в первый раз не было ошибки?**
- Сетевое соединение между Railway и GitHub нестабильное
- В первый раз могли попасть на другой сервер с лучшим соединением
- Это частая проблема при скачивании больших файлов с GitHub releases
